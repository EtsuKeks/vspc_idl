## Not covered (and why)

- Duplicate fulldivcode with different attributes in an INCR batch (R16, H13): 3.0's outcome depends on row order inside a Spark window: by the audit 3.0 writes PK twins / extra diff legs non-deterministically. No expectations; checked by repeated 3.0 runs (phase 1.4).
- Hash computed in the transformer's types (R03): with the real DDL every transformer column renders the same string as the target column, so the effect cannot appear.
- Inverted div_type interval on vanish, runs across midnight (D-14, M2), CTL parameters (D-12, D-13, D-20..D-24), failures and kills between publications (D-02..D-04, F of the audit), CTL/KAP call multisets (D-01, D-18, D-19): not data scenarios; they need a recording CTL mock / fault injection, which this stand does not have.
- Source type narrowing with overflow (bigint -> int, expected to FAIL in both versions, D-17): a failing load stops its chain, so it would need a chain of its own; not added to keep the runs short.
- Partial arrival 200 -> 90 keys (D-07): covered by the smaller 150 -> 40 of P01 (same thresholds).
- Performance (K of the audit): data is kept tiny on purpose.

Source columns a case may fill (gen.py rejects others) and the 3.0/4.0 code that reads them: `READS` in `synth/model.py`. Rule / change ids: `synth/rules_ref.py`.
